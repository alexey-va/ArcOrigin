# Native lead, attached cart and bounded work assignment

This change addresses the owner's 18 October corrections on Spawn. ArcOrigin 0.1.45 removes the custom authored route from the two player-led horse stages. The horse is attached once using `setLeashHolder(player)`; vanilla AI owns its path, slack and elastic movement. There is no player-ahead check, five-metre pause, six-metre detach, forced intermediate waypoint, custom velocity or timer-based reattachment. A broken lead is explicitly re-grabbed at ordinary interaction range; the horse and re-grab instruction become the current target.

The exact active Purpur 1.21.11 build 2568 and Citizens 2.0.43 build 4238 (`v1_21_R7`) establish the required native contract. Citizens otherwise clears goals for an NPC with Minecraft AI disabled and drops a protected NPC's leash. Only while a player leads their leased horse, the module enables the native AI/aware state and overrides `USE_MINECRAFT_AI=true`, `LEASH_PROTECTED=false`. Original metadata presence, value and persistence are retained. Transitions, cancellation and ownership-aware cleanup restore those settings before the care hold or autonomous return. NPC protection remains enabled, other players cannot leash or release an owned horse, and cleanup never mutates a replacement entity or a new lease.

Arrival uses the horse's actual position within the existing one-metre destination radius. Cross-ties, saddle, separate rider, actor leases and once-only whole-order payment remain. The owner-selected handoff is `67.5,70,-122.5`; Miron's home is `67.5,70,-120.5`. Authored navigation is retained for autonomous care/return/patrol, where the player is not leading the horse.

Wall-affixed work labels use a fixed plane with the authored wall-facing yaw and an outward offset. They do not rotate into masonry when the camera moves. The existing rings, ropes and destination frame keep their geometry.

Forge hauling uses the requested cart ground anchor `61.8,69,63.7` and source chest block `65,70,61`. The loop is source pickup, cart loading, explicit attachment, free movement with the player, destination unloading and whole-order acceptance. Chest menus and an empty return trip are not part of the job. The current source, actual cart display or destination is highlighted according to the stage. Model grounding and the final interaction details are recorded separately from runtime activation.

The waiting-for-next-order state has a 15-second assignment budget, fenced asynchronous status callbacks and fallback to another available offer. When no assignment can be obtained, the shift ends with an actionable reason and settles only already accepted work through the unchanged reward owner. An expired haul itself is not credited. The reported runtime incident entered this state after a copper haul expired; older logs do not identify which subsequent availability or lease check kept failing.

The cart uses the existing `cart_2` GROUND model at scale 3 with a measured 0.5625-block entity lift. The local model SHA-256 is `06fcde3cc7fdd62b8bcd5920dbd806c3867dd719abcae279c8fc11f58a3d425c`; the grounding calculation places its bottom at the requested Y=69 with zero residual. A read-only native placement check confirms dirt support and free body space at the cart and the actual chest at block `65,70,61`. This establishes placement inputs, not the final client rendering or active resource-pack identity.

Native metadata regressions use the real Citizens `SimpleMetadataStore`, rather than a map that conflates string keys and `NPC.Metadata`. Tests explicitly put the official unshaded `citizensapi:2.0.42-20260615.110519-11` before citizens-main's duplicated API because the latter's relocated Adventure namespace requires Citizens bootstrap. Production remains compile-only against the server-provided Citizens API.

Reward policy remains 20 Vault per accepted whole order and a shared 100 orders per UUID/UTC day (maximum 2000 Vault). The separate [cadence sensitivity](economy-native-lead-cart-20261018.json) models an unmeasured 50 percent improvement without changing the cap, reward journal, tokens, XP or permanent resources. Active SELL and the future SELL-to-contract transition remain separate and unchanged.

The owner explicitly stopped bot QA and will perform gameplay acceptance. No new bot, client run or native screenshot is used for this release. Source regressions, CI packaging, published bytes, on-disk delivery and activation are separate evidence; neither static native-contract inspection nor unit assertions prove the final feel of the lead or cart in a real client.
